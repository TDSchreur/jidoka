# Fast: Define

For a clear, bounded request, use the request as the spec and state a short implementation plan and acceptance criteria in the conversation; no tracker setup is needed for that. Save them as described in Saving the plan in the shared procedures included below, then continue directly to Build without separate spec files, tickets, or an approval round.

Use `jidoka-grill-with-docs` only when unresolved requirements or domain decisions materially affect implementation. Use `jidoka-to-spec` when the task needs a durable spec, and `jidoka-to-tickets` when multiple dependent pieces benefit from explicit tracking. Reuse existing specs and tickets rather than recreating them. Before reading or publishing specs or tickets in the tracker, follow Tracker setup in the shared procedures included below.

When these artifacts are needed, store them in the tracker configured in `docs/agents/issue-tracker.md`.

Follow Define rules in the shared procedures included below for the whole Define stage.
