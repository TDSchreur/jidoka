## Run reporting

Record stage summaries and ticket status with `jidoka run update <id>`; use `--ticket-status <reference>=in-progress` while working on a listed ticket and `--ticket-status <reference>=done` once finished. Record skill and activity reports at milestones. When outside input is needed, use `jidoka run block <id> --reason "<what is needed>"`. Use `jidoka run resume <id> --source "<what let work resume>"` when the block is resolved. Never include secrets. For options and continuation details, consult `jidoka-procedures/chunks/run-reporting.md` in the installed skills. Leave a stage with `jidoka run advance <id> --summary <stage>="<one or two sentences>" --activity "<what the next stage does>"`; it prints the next stage's instructions, so no separate `jidoka run next` or `jidoka run update` is needed. Advance saves the summary and activity only with a successful transition; when the gates refuse, address the blockers and include `--summary` and `--activity` again on the retry.

Read the whole output of `jidoka run advance` and `jidoka run next`. Never cut it with `head`, `sed`, `tail` or similar: later sections hold required steps.
