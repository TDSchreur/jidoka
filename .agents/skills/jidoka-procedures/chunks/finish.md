## Finish

Use `jidoka-pr` to write the pull request description. When the user chose to finish with remaining Check findings, list them in the description. Commit anything still uncommitted that belongs to the change as a new commit. Verify the final commit before pushing: reuse the latest passing full verification when the final commit contains exactly the checked code and its relevant inputs are unchanged, otherwise run the project's verification on it. Report the result; do not open the pull request while a check fails or cannot run. Then follow the `jidoka-procedures/references/pull-request-and-ci.md` file in the installed skills to open the pull request, and read it again while watching CI. The Finish report tells the user to run `jidoka run cleanup <id>` once the pull request merges.
