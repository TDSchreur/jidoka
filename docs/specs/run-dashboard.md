# Show factory runs on the dashboard

The dashboard should show progress when an agent uses factory. The local Rust server owns durable run records and provides them to the dashboard. The factory skill registers a run and updates its stage as work progresses; completed and blocked work remain visible. The dashboard refreshes automatically and clearly reports when the server is unavailable.

Keep the system local and small: a run needs a title, project, stage, and status. The CLI talks to the server, so the skill does not manipulate stored data directly. Starting the dashboard starts the server. Existing runs survive a server restart. Do not require a database or external service.

Verify run creation and updates, persistence across restart, invalid requests, and dashboard display. Preserve the existing CLI help and version commands.

The board groups runs into rows by project, sorted by project name. Each row has a column per stage, with blocked runs first.

The Reader shows a run's local spec or ticket, a recorded reference that is not an http(s) link, as rendered Markdown in a dialog over the run's detail. A View link in the run row and the detail opens the spec, and a local ticket's title opens that ticket. The dialog says when the file is no longer available and closes with Close or Escape without closing the detail.

`GET /api/runs/<id>/document?reference=<reference>` serves it. Only the run's recorded spec and ticket references are served, and only `.md` files up to 1 MB. A relative reference resolves against the run's worktree, then its repository. The canonical path must be inside the worktree, the repository (each must be a git root: not a filesystem root, with a `.git` entry), the worktree's git directory (a `gitdir:` file counts only when it points into the repository's `.git`), or `<worktree>.factory-plan.md`. UNC and device paths are refused. A run's plan is saved in the factory data folder, not in the worktree: `plans/<run id>.md` beside `runs.json`, or `plans-<port>/<run id>.md` beside `runs-<port>.json` for a dashboard on another port. `factory run begin` and `factory run inspect` print the path (`plan` in `--json`), the folder is created private (0700) when they first show it, and `factory run cleanup` leaves the plan. A missing file answers 404 with `{"available":false,"path":...}`. A symlink swapped in between the path check and the read is not guarded against: that needs write access inside the run's worktree or repository, and the dashboard is local-only. The server renders the Markdown, escapes raw HTML and keeps only http(s) links.
