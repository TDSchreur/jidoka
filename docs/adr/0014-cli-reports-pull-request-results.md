# CLI reports pull request results to the dashboard

The CLI reads pull request state from the host and posts the result to the dashboard so the cache and run transition are saved together. The endpoint accepts the local CLI token and trusts the client-provided URL, state and read-start timestamp; possession of the token already authorizes run updates. Rechecking the host in the server would duplicate the request and could produce a different result. A missing run returns 404, a superseded result returns 409, and an accepted result returns a boolean indicating whether the run transitioned. Results for the same URL are ordered by read-start milliseconds; on a tie, merged wins over closed, which wins over other states, and otherwise the first result wins. A recorded merge is terminal. These rules make ties deterministic but cannot distinguish two nonterminal reads started in the same millisecond.
