**Breaking:** a run's stage now changes only through `jidoka run advance` (and the Rework path). `jidoka run update <id> <running|blocked|done> [options]` no longer takes a stage, and an API update with a `stage` field is rejected. `done` is accepted only while the run is at Finish. Update no longer prints stage warnings. `--rework <n>` on a running run in Check moves it back to Build (the run's mode must be recorded); elsewhere it only sets the count. For the rare case a gate cannot be met, `jidoka run advance <id> --force --reason "<text>"` skips the gates, follows the stage graph and records the reason on the run.
