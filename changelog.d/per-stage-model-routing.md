## Changed

- The model-routing policy maps each Stage to a model and optional effort under `agents.<agent>.stages` (`define`, `build`, `check`, `finish`), and the starter favours cheap models and low effort. Roles, tasks and the single-agent form are gone. `factory install`, `factory update` and `factory doctor --create-model-routing` replace a `model-routing.json` in the earlier format with the new starter and print its path, what is switched off and how to switch it on; a newly created starter prints how to edit it or switch it off with `"enabled": false`; custom values are not migrated. A switch that was off in the earlier file stays off in the starter (the whole policy, or an agent entry; the single-agent form carries only the top-level one). A current-format, unparseable or unrecognised file and a symbolic link are left alone. Until replaced, an earlier-format file stops `factory run start` with an error that says to run one of those commands.
- `factory run update --model-routing` takes `<stage>=<model>[:<effort>]` instead of `<task>=<role>`. `factory run inspect` shows each Stage's model and effort or "not routed", and `factory doctor` checks the model and effort of every routed Stage. The API accepts only the new shape, and runs recorded with the earlier routing shape read as not routed.
- The workflow skills route every Stage, not only Check. The coordinating session keeps its own model and the interview; Define's spec, tickets and fact-finding, each Build ticket and Rework, Check's review agents, and Finish's pull request description and CI fixes run in fresh agents on that Stage's model and effort. Each Stage summary says which model its agents ran on, or why routing did not apply.
